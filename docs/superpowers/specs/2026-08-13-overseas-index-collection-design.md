# AF-110 해외 지수 수집 설계

- 작성일: 2026-08-13
- 선행: AF-101(국내 지수 수집) 완결 · AF-103(수집 스케줄러) 가동 중
- 후속: AF-104 시장 화면 해외 탭
- 노션: AF-110 (P1 가시화, 규모 M, 영역 BE)

## 전제가 바뀌었다 — Twelve Data가 필요 없다

노션 카드와 AF-101 설계 문서는 *"한투 커버리지가 부족한 해외 지수는 Twelve Data로 보완"* 이라고
적었다. **가정이었고 확인해보니 틀렸다. KIS가 9종을 전부 커버한다.**

이 변경이 없애는 것:

- **Twelve Data API 키 발급** — 사용자 작업이 사라진다
- **무료 플랜에 지수 심볼이 있는지 확인** — 해당 없음
- **AF-108이 확정한 "Twelve Data 무료 티어는 제3자 재배포 불가"** — 해당 없음.
  약관 질문이 이미 걸려 있는 KIS 하나로 합쳐진다

검토했으나 택하지 않은 대안:

- **KRX Open API** — 한국거래소라 **해외 지수를 주지 않는다.** 게다가 지수 실시간 시세는
  "KRX 지수 라이선스와 별개로 코스콤에 별도 문의"라 국내 약관 문제도 우회되지 않는다
- **토스증권 Open API**(2026년 개시) — 실재하는 새 선택지이나 지수 커버리지·약관 미확인.
  KIS로 되는 것을 확인한 이상 벤더·계정·약관 검토를 하나씩 더 늘릴 이유가 약하다.
  **KIS가 막히면 1순위 대안이다**

## 엔드포인트 — 운영 실측으로 확정

```
GET /uapi/overseas-price/v1/quotations/inquire-daily-chartprice
tr_id: FHKST03030100
FID_COND_MRKT_DIV_CODE=N   (해외지수)
FID_INPUT_ISCD=<코드>
FID_INPUT_DATE_1=YYYYMMDD  FID_INPUT_DATE_2=YYYYMMDD
FID_PERIOD_DIV_CODE=D
```

**현재가만 주는 엔드포인트는 없다.** 이것과 분봉(`inquire-time-indexchartprice`) 둘뿐이고
둘 다 시계열이다. 우리 주기가 "종가 정본 + 장중 지점"이라 일봉이 오히려 잘 맞는다.

## 지수 코드 — KIS 마스터에서 1차 확인

`https://new.real.download.dws.co.kr/common/master/frgn_code.mst.zip`을 받아 파싱했다
(AF-111이 국내에 쓴 것과 같은 방법). **이미 아는 `SPX`가 `S&P 500 INDEX`로 나오는 것으로
파싱 규칙을 먼저 검증한 뒤** 나머지를 읽었다.

| 지수 | 코드 | 구분 | 실측 확인 |
|---|---|---|---|
| S&P 500 | `SPX` | P | ✅ |
| 나스닥 종합 | `COMP` | P | ⬜ |
| 다우존스 | `.DJI` | P | ✅ `다우존스 산업지수` |
| 나스닥 100 | `NDX` | P | ⬜ |
| VIX | `VIX` | P | ⬜ |
| 니케이 225 | `JP#NI225` | W | ⬜ |
| 항셍 | `HK#HS` | W | ✅ `항셍지수` |
| 상해종합 | `SHANG` | W | ⬜ |
| 유로스톡스 50 | `SX5E` | W | ⬜ |

미국계는 구분코드 `P`, 아시아·유럽계는 `W`이며 `국가#심볼` 형태다.
**`P`와 `W`의 응답 형태가 같아 파서를 하나로 쓴다.**

### ⚠️ 비슷한 이름이 줄줄이 붙어 있다

나스닥100 옆에 `XNDXL`(레버리지)·`XNDXS1/S2`(인버스), 항셍 옆에 `HSCE`(홍콩H)·`HK#HSSI`(소형주),
상해에 `CH#SHA`/`CH#SHB`(A주·B주), 다우 옆에 `.DJT`(운송)·`.DJU`(유틸리티)·`.DJINET`(인터넷).

**틀린 걸 넣으면 화면에 "항셍"이라 쓰인 채 홍콩H지수가 뜬다.** `IndexGuards`는 값끼리의
정합성만 보므로 엉뚱한 지수도 그대로 통과한다 — 예외도 경고도 없이 그럴듯한 숫자가 저장된다.

→ **`hts_kor_isnm`이 사람이 눈으로 잡을 유일한 수단이다.** 미확인 6종은 배포 후
`raw-overseas`로 한 번씩 찍어 이름을 대조할 것.

## 국내와 다른 점 — 여기가 설계의 실질이다

### 1. 거래일이 응답에 있다

**국내 설계의 가장 큰 제약이 여기선 사라진다.** 국내는 응답에 기준시각이 없어 `trade_date`를
주입된 시각의 KST 날짜로 유추했다. 해외는 `output2[].stck_bsop_date`가 거래일을 직접 준다.

→ **`trade_date`는 응답에서 읽는다. 시계로 유추하지 않는다.**

부수 효과로 **국내가 감수하기로 한 "장 시간이 옮겨지는 날" 문제를 해외에선 안 겪는다**(#147).
15:50에 돌든 17:00에 돌든 봉이 자기 날짜를 들고 오기 때문이다.

### 2. 전일 종가를 직접 준다 — 가드가 한 겹 강해진다

국내는 `현재가 − 전일대비`로 역산했다. 해외는 `ovrs_nmix_prdy_clpr`로 직접 온다.
**실측 3건 모두 역산값과 정확히 일치했다.**

→ **`역산 == 응답값`을 가드에 추가한다.** 국내에 없던 검증이고, 소수점 위치나 필드 오배치를
등락률 검사와 독립적으로 잡는다.

**그래서 `prev_close`에는 응답값이 아니라 역산값을 저장한다.** 응답값을 그대로 넣으면 비교할
독립적인 출처가 하나도 남지 않아 이 가드가 자기 자신과의 비교가 된다 — 조용히 영원히 통과한다.
응답값은 검증용으로만 따로 들고 다닌다(`OverseasIndexReading.reportedPrevClose`).
아래 저장 매핑표도 이 규칙을 따른다.

### 3. `prev_close_date`를 채운다

국내 경로는 응답에 없어 NULL로 뒀다. 해외는 `output2[1].stck_bsop_date`가 그것이다 —
실측에서 그 봉의 종가가 `ovrs_nmix_prdy_clpr`와 일치함을 확인했다.

**해외에서 이게 특히 중요하다.** 한국 월요일 아침에 보는 S&P의 "전일"은 미국 금요일 종가다.
화면이 어느 날 대비인지 말할 수 없으면 사용자가 숫자를 오해한다.

### 4. 진행 중인 봉을 구분할 수 있다

실측에서 항셍의 최신 봉이 **오늘**(`20260813`)이고 거래량이 `0`이었다 — 홍콩장이 안 닫혔다.
반면 다우·S&P는 최신 봉이 어제라 확정된 종가다.

**거래량으로는 판정할 수 없다.** SPX는 확정된 봉도 항상 `acml_vol: "0"`이다(지수라 거래량
개념이 없다). 거래량을 신호로 쓰면 **S&P가 영원히 "진행 중"이 된다.**

→ **최신 봉의 `stck_bsop_date`가 그 시장의 현지 오늘이면 진행 중**으로 본다.

**진행 중인 봉도 저장한다.** 버리면 장중에 화면이 비고, 확정인 척하면 거짓말이 된다.
`market_status`를 `장중`으로 넣어 화면이 그대로 말하게 한다.

### 5. 필드명이 전혀 다르다

국내 `bstp_nmix_prpr` vs 해외 `ovrs_nmix_prpr`. **파서를 공유할 수 없다.** 별도로 만든다.

### 6. 부호 규약 — 국내에서 못 푼 것이 여기서 풀렸다

국내는 실측일이 상승일이라 하락일 표현을 확정하지 못했고, "값은 절댓값으로만 쓰고 방향은
`prdy_vrss_sign`에서만" 이라는 방어적 규칙을 세웠다.

**해외 실측에서 하락일이 잡혔다** — 항셍 `vrss: -75.03 / sign: 5 / ctrt: -0.29`,
다우 `-21.58 / 5 / -0.04`. **KIS는 값에 마이너스를 실어 보낸다.**

그리고 **국내 규칙이 그대로 맞다.** 절댓값에 방향을 곱하면 원본이 재현되고
(`|−75.03| × −1 = −75.03`), 모순 검사(값 음수 + sign 하락 = 일관)도 정확히 통과한다.
어느 관례든 결과가 같게 만든 설계가 실제 데이터로 검증됐다.

→ **국내 파서의 부호 규칙을 그대로 가져간다.**

## 저장

**기존 `market_index_quote`를 그대로 쓴다. 스키마 변경 없다.**

| 컬럼 | 해외 경로 |
|---|---|
| `index_code` | 우리가 정한 canonical (`SPX`, `NASDAQ`, `DOW`, …) |
| `trade_date` | **`output2[0].stck_bsop_date`** (응답에서) |
| `slot` | **`CLOSE` 고정** — 일봉이라 하루 한 건 |
| `price` | `output2[0].ovrs_nmix_prpr` |
| `prev_close` | **`price − change`로 역산** — 응답의 `ovrs_nmix_prdy_clpr`를 그대로 넣지 **않는다** |
| `change_value` · `change_rate` | 절댓값 × `prdy_vrss_sign` 방향 |
| `prev_close_date` | **`output2[1].stck_bsop_date`** |
| `market_status` | 최신 봉이 현지 오늘이면 `장중`, 아니면 `장마감` |
| `source` | `KIS_OVERSEAS` |

`slot`을 `CLOSE`로 고정하는 이유: 하루에 봉이 하나뿐이라 슬롯 개념이 필요 없고, 같은 날 다시
수집하면 같은 키로 덮어써야 한다. 국내가 슬롯을 쓴 이유(응답에 시각이 없어 조회 시각이
데이터에 새겨짐)가 여기선 성립하지 않는다.

## 스케줄

AF-101 설계 문서가 정한 것을 그대로 따른다.

| 대상 | cron (UTC) | KST | 근거 |
|---|---|---|---|
| 미국 | `30 21 * * 1-5` | **익일** 06:30 | 마감 16:00이 EDT면 20:00 UTC·EST면 21:00 UTC. 21:30은 양쪽 다 마감 이후라 **서머타임 분기가 없다** |
| 아시아 | `30 8 * * 1-5` | 17:30 | 니케이(15:00 JST)·항셍(16:00 HKT)·상해(15:00 CST) 마감 후 |
| **유럽** | `30 21 * * 1-5` | **익일** 06:30 | 유로스톡스 마감 15:30 UTC의 6시간 후 — 아래 참조 |

**cron의 `1-5`는 UTC 요일이다.** 금요일 21:30 UTC 실행은 토요일 06:30 KST에 떨어지지만
잡는 것은 **금요일 미국 종가**다 — 의도한 동작이다. 한국 요일에 맞추려고 `1-5`를 손대면
금요일 미국 종가를 통째로 놓친다.

### 유로스톡스는 아시아 슬롯이 아니라 미국 슬롯에 넣는다

마감 17:30 CEST = **15:30 UTC**다. 아시아 슬롯(08:30 UTC)은 **마감 7시간 전**이라
그날 종가를 못 받고, 미국 슬롯(21:30 UTC)은 **마감 6시간 후**라 받는다.

일봉이 자기 날짜를 들고 오므로 아시아 슬롯에 둬도 **데이터가 틀리지는 않는다** — 전일 종가가
전일 날짜로 정확히 저장될 뿐이다. 다만 화면이 늘 하루 뒤처진다.

전용 슬롯(예: 16:00 UTC)을 새로 파지 않는 이유는 Render 기동이 한 번 더 늘기 때문이다.
6시간 늦게 받아도 종가는 종가라, 그 대가를 낼 값어치가 없다.

## 안전장치

국내 `IndexGuards`를 재사용하되 해외 전용 검사를 더한다.

- **등락률 자기모순** (국내와 동일) — `change / prevClose × 100` vs 응답값, 허용오차 0.05%p
- **전일종가 교차검증** (해외 신규) — `price − change == ovrs_nmix_prdy_clpr`
- **0 또는 음수 현재가 거부** (국내와 동일)
- **부호 모순 거부** (파서에서, 국내와 동일 규칙)

**급변동 가드는 두지 않는다** — 국내와 같은 이유다. 지수는 폭락일에 10%도 넘게 움직이고
그런 날일수록 데이터가 필요하다.

## 요청 구간

`FID_INPUT_DATE_1`/`2`가 필수다. **최근 7일을 요청한다** — `output2[1]`(전일 봉)이 있어야
`prev_close_date`를 채울 수 있고, 연휴가 끼면 직전 거래일이 며칠 전일 수 있다.

## 범위 밖

- **시장 화면**(AF-104) — 이 태스크는 수집까지다
- 분봉(`inquire-time-indexchartprice`) — 일중 차트가 필요해지면 그때
- 미확인 6종의 코드 검증 — 배포 후 `raw-overseas`로 `hts_kor_isnm` 대조. 코드 자체는
  설정(`market-index.overseas`)으로 빼 두므로 틀리면 한 줄로 고친다
